# Oddio UX roadmap: audit after the mobile player and Story releases

Reviewed `main` at `55f1932` against [the original 13-phase plan](UX_DEVELOPMENT_ROADMAP_2026.md). The phase table in that file is a historical starting snapshot. The roadmap umbrella shipped in PR #31 (`d905658`), first-run genre selection in #32, mobile optimization in #33–36 and #38, and Story fixes in #39. A shipped phase is not evidence that all of its original acceptance criteria were met.

## This follow-up

- Retain a valid Rewind year when guests are sent to login, without carrying arbitrary query parameters. Test password sign-in and the returned report in both locales.
- Prevent a device from replacing newer account lists before initial sync or after editing a stale copy. The server performs a conditional write scoped to the signed-in account and the last observed version. On conflict the user can choose which copy to keep; neither is replaced silently. The on-device fallback still works when account storage is unavailable.
- The browser suite uses isolated local demo sessions and a controlled account endpoint to simulate two devices, a slow initial read and an offline edit. The route suite exercises the real Supabase client against an isolated Data API fixture. Neither verifies the live Supabase project. No schema or production data change is part of the patch.
- Before release, run the new GitHub checks on the final commit. Before calling sync production-verified, exercise fresh sign-in, save/refresh/reconnect and an offline conflict using an isolated Oddio database and disposable accounts. Then move to physical-device playback and field measurement.

Oddio 2.0 (PR #37) is a separate release and is unchanged by this work.
